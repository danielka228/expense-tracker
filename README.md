# СпендТрекер — трекер расходов

Веб-приложение: регистрация, вход, траты по дням с заметками, статистика за день/неделю/месяц
и по категориям, рейтинг друзей, фото профиля, быстрые траты с iPhone через «Команды».

Работает на **Cloudflare Workers**, база данных — **Cloudflare D1** (SQLite). Сайт не «засыпает», как на бесплатном Render.

Сайт: https://expense-tracker.hhoh7327.workers.dev

**Обновление сайта:** после мержа в `main` GitHub сам выкладывает новую версию на Cloudflare
(Actions → «Переезд на Cloudflare»). Нужны секреты `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`.

**Сканер покупок:** кнопка «Сканировать» открывает камеру. Наведи на штрих-код — сайт найдёт товар
в открытой базе Open Food Facts, по геопозиции предложит магазин рядом (данные OpenStreetMap) и подставит цену
из прошлых покупок этого товара. Геопозиция запрашивается только в момент сканирования.

**Демо-версия:** `expense-tracker-preview` — отдельный сайт со своей базой и кнопкой «Войти в демо-аккаунт».
Выкладывается вручную: Actions → «Переезд на Cloudflare» → Run workflow → target: `preview`. Основной сайт не трогается.

**Голосовой ввод:** кнопка «Голосом» на главной. Скажи, например, «кофе с другом 350»,
«вчера такси 1 200» или «2 тысячи на продукты» — сумма, категория, заметка и дата заполнятся сами.
Пока говоришь, эквалайзер показывает звук с микрофона. Работает в Safari и Chrome.

**Подписки:** вкладка «Подписки» — Netflix, музыка, связь, спортзал и всё, что списывается регулярно.
Видно, сколько уходит в месяц и в год, какая подписка дороже всех и что спишется в ближайшую неделю.
Подписку можно завести в любой валюте (например, ChatGPT за $20): итоги пересчитываются в валюту аккаунта.
В день списания трата записывается сама (утром по расписанию или при открытии сайта), а накануне бот
напоминает в Telegram, чтобы успеть отменить ненужное. В боте подписки тоже есть: кнопка «🔁 Подписки» в меню
или /subs — итоги, ближайшие списания, автозапись и удаление; добавить можно прямо в чате: выбрать сервис
и написать сумму и число («399 15») или свою подписку целиком («Бассейн 3000 5»).

**Telegram-бот:** пишешь или надиктовываешь голосовым «кофе 250» или «вчера такси 540», и трата появляется на сайте.
Голосовые распознаёт Whisper на Cloudflare Workers AI (до минуты; в бесплатном лимите Cloudflare).
Бот угадывает категорию; под каждой записью есть кнопки «Категория» и «Удалить».
Всё остальное — в меню с кнопками (/menu): добавить трату с выбором категории, статистика за день/неделю/месяц,
список трат с поиском по страницам, рейтинг друзей, валюта и отключение бота. Меню живёт в одном сообщении
и перерисовывается на месте. Кнопка «СпендТрекер» слева от поля ввода и «📱 Открыть СпендТрекер» открывают сайт
прямо в Telegram (Mini App) — вход в аккаунт происходит сам, по подписи Telegram.
Подключение: на сайте «Профиль» → «Подключить Telegram».

В любом чате (с другом, в группе) можно написать `@ник_бота сигареты 250` и нажать на карточку «Записать»:
трата запишется, а в чате появится сообщение о ней с кнопками. Для этого в @BotFather один раз нужно включить
инлайн-режим: `/setinline` (подсказка, например «кофе 250») и `/setinlinefeedback` → Enabled.

Как включить бота (один раз):
1. В Telegram открой @BotFather → `/newbot`, придумай имя и ник бота (ник должен заканчиваться на `bot`).
   BotFather пришлёт токен вида `123456789:AAE…`.
2. В GitHub: Settings → Secrets and variables → Actions → New repository secret,
   имя `TELEGRAM_BOT_TOKEN`, значение — токен. Токен никому не отправляй.
3. Запусти выкладку: Actions → «Переезд на Cloudflare» → Run workflow (или просто влей PR).
   Workflow сам передаст токен в Cloudflare и подключит бота к сайту.

## Что внутри
- `src/index.ts` — вся логика (маршруты, работа с базой)
- `src/views.ts`, `src/styles.ts` — страницы, виджеты и тёмная тема
- `src/client.ts` — скрипты для браузера: голосовой ввод, эквалайзер, анимации
- `src/lookup.ts` — поиск товара по штрих-коду и магазинов рядом, история цен
- `src/parse.ts` — разбор фраз «кофе 250» (общий для голосового ввода и Telegram-бота)
- `src/telegram.ts` — Telegram-бот
- `src/subs.ts` — подписки: даты списаний, автозапись трат, тексты
- `public/` — иконка приложения; `public/vendor/` собирается из npm при деплое (распознаватель штрих-кодов для iPhone)
- `src/passwords.ts` — проверка паролей; старые пароли из Flask-версии подходят
- `migrations/0001_init.sql` — схема базы D1
- `migrate/export_to_d1.py` — перенос всех данных со старой базы Render в D1
- `wrangler.jsonc` — настройки Cloudflare

Старая Flask-версия (`app.py`, `*.html`, `requirements.txt`, `Procfile`) пока лежит в репозитории,
чтобы Render продолжал работать до переезда. После переезда эти файлы можно удалить.

## Переезд с Render на Cloudflare (один раз)

Нужен Node.js 20+ и Python 3.

1. **Установи зависимости и войди в Cloudflare**
   ```bash
   npm install
   npx wrangler login
   ```

2. **Создай базу D1**
   ```bash
   npx wrangler d1 create expense-tracker
   ```
   Скопируй `database_id` из вывода в `wrangler.jsonc` (вместо нулей) и создай таблицы:
   ```bash
   npm run db:migrate
   ```

3. **Задай секретный ключ** (любая длинная случайная строка, можно не ту, что была на Render):
   ```bash
   npx wrangler secret put SECRET_KEY
   ```

4. **Задеплой сайт**
   ```bash
   npm run deploy
   ```
   Wrangler покажет адрес вида `https://expense-tracker.<твой-аккаунт>.workers.dev`.

5. **Перенеси данные.** Делай это прямо перед переключением, чтобы не потерять свежие траты.
   - На Render открой Web Service → **Settings → Suspend**, чтобы никто не добавлял траты во время переноса.
   - На Render открой базу PostgreSQL → **Connect → External Database URL**, скопируй.
   - Выгрузи и загрузи данные:
     ```bash
     pip install sqlalchemy psycopg2-binary
     python migrate/export_to_d1.py "ВСТАВЬ_EXTERNAL_DATABASE_URL" migrate/dump.sql
     npx wrangler d1 execute expense-tracker --remote --file=migrate/dump.sql
     ```
   Скрипт покажет, сколько перенесено пользователей, трат, друзей, фото и токенов.
   Загружать дамп нужно в пустую базу: при повторной загрузке будут ошибки из-за совпадающих ID.

6. **Проверь** новый адрес: зайди под своим логином и паролем, всё должно быть на месте.
   После этого сервис и базу на Render можно удалить.

### Что поменяется для пользователей
- Логины, пароли, траты, заметки, друзья, фото и токены сохраняются.
- Всем один раз придётся заново войти (сессии со старого сайта не переносятся).
- **iPhone-команда «Трата»** отправляет запросы на старый адрес `...onrender.com/api/add`.
  Открой команду в «Командах», замени адрес на `https://<новый-адрес>/api/add`,
  поделись ей заново и задай новую ссылку на iCloud:
  ```bash
  npx wrangler secret put SHORTCUT_URL
  ```
  Тем, кто уже поставил команду, нужно поменять адрес у себя. Токены остаются прежними.
  Если подключить к Worker свой домен (Cloudflare → Workers → Settings → Domains & Routes),
  адрес больше никогда не придётся менять.

### Тариф Cloudflare
На бесплатном тарифе Workers запросу даётся 10 мс процессорного времени. Пароли старых
пользователей зашифрованы алгоритмом scrypt, и его проверка занимает около 100 мс, поэтому
первый вход старого пользователя на бесплатном тарифе может упасть с ошибкой. После первого
успешного входа пароль автоматически пересохраняется в более лёгком формате.
Надёжный вариант — тариф Workers Paid ($5/мес, лимит 30 секунд).

Открой в браузере: http://localhost:8787

## Режим питания

В настройках выбери **Режим приложения → Питание**. Выбор хранится в аккаунте;
обычный режим расходов и его данные сохраняются. В дневнике можно выбрать дату,
добавлять и исправлять приёмы пищи (вес в граммах и ккал на 100 г), видеть дневной итог.
Покупки продуктов хранятся отдельно от съеденных порций: «Записать порцию» копирует
продукт и предлагает указать съеденный вес. Цена при создании покупки необязательна;
если она указана, одновременно создаётся расход в категории «Еда» в валюте аккаунта.
Удаление записи питания не удаляет расход; его можно изменить в режиме расходов.
Это дневник, а не склад: запись порции не уменьшает купленный вес.

В «Заполнить по фото с ИИ» можно загрузить еду или обратную сторону упаковки.
Анализ начинается автоматически после выбора фото: ИИ сам определяет тип снимка,
название блюда и предлагает калорийность и, когда возможно, примерный вес порции.
Используется существующий Workers AI binding `AI` и модель Gemma; отдельный API-ключ
не нужен. При неясном составе, масле, весе или нечитаемой этикетке ИИ задаёт вопросы.
Ответы вводятся в поле под фото и отправляются повторно с тем же изображением.
Результаты — редактируемые предложения, ничего не сохраняется автоматически.
Фото сжимаются в браузере, отправляются в Workers AI для анализа и не хранятся в D1.
Без AI работают ручной ввод и весь дневник. Лимит распознаваний общий с другими фото.

Перед обновлением Worker нужна миграция `0015_nutrition.sql` (существующий workflow
применяет миграции перед деплоем). Старые аккаунты получают режим «Расходы» по умолчанию.

Проверки (Node.js 22.18+):
```bash
npm run typecheck
node --test tests/nutrition.test.mjs
node --check public/nutrition.js
```
`tests/nutrition-integration.mjs` запускается против **изолированного локального** Worker
на `http://localhost:8787` без AI binding, с применёнными миграциями; создаёт два тестовых
аккаунта. Не запускать против production. Проверяет доступ, режимы, записи, покупки,
чужие данные, валидацию, CSRF и ограничение размера загрузок.

Доработки дневника: отдельные ответы на вопросы ИИ, отмена распознавания,
защита ручных правок от поздних ответов, отметки «оценка ИИ / с этикетки»,
переход между соседними днями и предупреждение о несохранённых изменениях.
Повтор сохранения после сетевого сбоя не создаёт вторую запись или трату;
для этого нужна также миграция `0016_nutrition_reliability.sql`.
Смена фото очищает прежние автоматические значения. Ручной вес сохраняется,
а примерный вес ИИ может быть пересчитан после уточнения.

Дополнительные проверки:
```bash
npm run test:nutrition
# Установленный Chromium; путь можно задать через CHROMIUM_PATH
npm run test:nutrition:browser
```
Браузерные проверки используют подставленные ответы модели: проверяют интерфейс,
но не качество реального распознавания. В демо-окружении отдельно задан binding AI,
чтобы фото работали и в preview.

## iOS-приложение (xtool)

`ios/SpendTracker/` содержит SwiftUI-оболочку сайта для сборки через xtool на Linux/WSL:
она сохраняет сессию WebKit между запусками, открывает ссылки Telegram в приложении Telegram,
использует нативное распознавание речи, если WebKit его не поддерживает, передаёт системные запросы
доступа к камере и микрофону, ускоряет анимацию элементов управления.
Кнопка входа Telegram в приложении запускает системное окно iOS: после подтверждения Telegram
возвращает пользователя в приложение, а сервер передаёт ему сессию по короткоживущему одноразовому билету.
Для этого серверная версия должна быть обновлена вместе с миграцией `0017_app_auth_tickets.sql`.
Иконка берётся из брендинга сайта. Если исходники репозитория доступны в Ubuntu, запусти скрипт установки оболочки:

```bash
bash /path/to/expense-tracker/ios/SpendTracker/install.sh ~/ExpenseTrackerTest
```

Он скопирует файлы и добавит `infoPath` и `iconPath` в существующий `xtool.yml`, сохранив `bundleID`.
Затем запусти `xtool dev`.
При первом голосовом вводе iOS может отдельно спросить доступ к распознаванию речи и микрофону;
камера запросит разрешение при первом сканировании или фото. Выбор хранится в настройках iOS.

Такой способ устанавливает приложение на зарегистрированный iPhone для разработки;
для публикации в App Store понадобится отдельная подготовка и платное членство Apple Developer.
